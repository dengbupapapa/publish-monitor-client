# Design

## Context

动机见 `proposal.md - Why`；行为契约见 `specs/match-result-list/spec.md` 与
`specs/match-result-detail/spec.md`。此处只记录约束与取舍。

现状与关键约束：

- 本仓库只有 Vue 3 + Vite 脚手架（`App.vue` 占位、空 `router/index.js`、`stores/counter.js`），
  无任何业务代码与既有 spec。`pnpm-lock.yaml` 表明包管理器是 pnpm。
- 后端 `publish-compliance-monitor` 提供两个只读接口，`GET /match-results` 与
  `GET /match-results/{id}/preview`；服务默认监听 `127.0.0.1:8001`，**未配置 CORS 中间件**。
- 详情接口返回的是**落库形态**五键结构 `{article, records, ranges, alignment, objects}`：
  记录不含文本、区间是扁平行、对齐是六列扁平行、没有高亮注入计划。
- 后端已有一份"精简对比预览"的离线 HTML 渲染器（模板 + 桥接层），它消费的是另一套
  `page` 契约（`sides[side].body/injectPlan`、记录带 `text`、对齐是嵌套形态）。
  两者的差就是本设计要补的一层桥接。
- 该类页面的既有行为在 spec `md-diff-preview-viewer` / `md-diff-preview-data` 中被固化，
  本次实现把其中**渲染与交互**部分作为基线，把**离线产物打包**部分显式排除。

参考数据规模：单篇格式化正文 50–150 KB（`data/` 样例），行原子数量可达上百。

## Goals / Non-Goals

**Goals:**

- 只吃现有两个接口，后端零改动。
- 渲染内核与后端离线页在相同输入下产出相同的行数、单侧行数、连线端点数、高亮处数、卡片摘要。
- 算法层是可单测的纯函数，不依赖 Vue 与 DOM（除渲染与测量两处）。
- 降级路径保留且可观测。

**Non-Goals:**

- 不实现源码视图、渲染骨架自检、诊断面板、对象配对表、候选数/丢弃数统计。
- 不做虚拟滚动、不做分页渲染对照区。
- 不做写入类操作（触发运行、定时任务）、不做跨域方案。
- 不追求与离线页样式像素一致；只保证渲染语义与交互行为一致。

## Decisions

### D1. 桥接层放前端，不新增后端接口

详情接口给的是落库形态，渲染契约需要的三样东西（注入计划、记录摘要、嵌套对齐）在前端补齐。

- 放弃的方案：后端新增 `GET /match-results/{id}/page` 直接返回 `page`。优点是前端不做算法移植；
  缺点是要改另一个仓库、要新增 spec、且偏离"只用这两个接口"的约束。
- 代价：同一套算法存在两份实现。缓解办法是把后端的离线 HTML 产物当作对照基准（见验收），
  差异只会表现为降级横幅，不会错位。

### D2. 以查询结构为渲染起点，取消 `injectPlan` 作为中间数据

`ranges` 行自带 `record_id`，`change_kind` 从 `records` 查表即得，因此可以直接由区间行构造
该侧 span 列表并注入高亮，不需要先装配 `records[].{side}.{ranges,text}` 再摊回去。

```text
 preview(id) ──► {article, records, ranges, alignment}
                      │
        ┌─────────────┴───────────────────────────────┐
        │ 纯函数层 (src/diff, 无 Vue 依赖)             │
        │  spansOfSide -> buildInjectPlan -> injectMarks
        │  lexBlocks -> planAtoms/applyAtoms -> buildBlocks
        │  covered / planRows / sliceText / recordLabel
        └─────────────┬───────────────────────────────┘
                      ▼
              两侧 atoms HTML + rows[{reference,i|−1, input,j|−1}]
                      ▼
        ┌─────────────────────────────────────────────┐
        │ 呈现层 (Vue)                                 │
        │  DiffWorkspace: 表头 + 单滚动容器 + overlay SVG│
        │  DiffRow: 两侧 v-html 原子                    │
        │  RecordCard: 徽章 + 处数 + 摘要 + 第 k/N 行    │
        └─────────────────────────────────────────────┘
```

记录摘要只为卡片服务，因此不预切全文，按需切片（卡片最多显示 40 字）。

### D3. 算法的"冻结清单"与"不移植清单"

必须逐条对齐后端实现，改动即视为破坏契约：

| 保留项 | 原因 |
| --- | --- |
| `unsafeReason` 的五条判据 | 少一条就可能把 `<mark>` 插进图片/链接语法，正文直接裂开 |
| 不安全区间跳过（不裁剪）+ 重叠区间合并 | 裁剪会移动语义；不合并会产生嵌套标记 |
| `lexBlocks`：`token.raw` 顺序累加，顶层列表按 `items[].raw` 逐项切分，累加必须等于正文长度 | 这是"源码偏移 ↔ 渲染元素"的唯一桥梁 |
| `planAtoms` / `applyAtoms`：列表按项拆容器，有序列表逐项写回起始序号 | 对齐层是"一个列表项一块" |
| 区间数 ≠ 原子数 → 返回空（进入降级） | 这是降级开关，不是错误处理 |
| `covered`：右边界以"块起点 < 区间结束"判定 | 块尾空行归属区间，用 `end-1` 探测会多算下一块 |
| `planRows`：游标只认自区间内、且未被前条目吃掉的块；条目两侧按序 1:1；剩余块各自成行；最后做单调性与全覆盖自检 | 自检失败必须退化，不能拿错位布局凑合 |
| 连线 k↔k 纵向配对、单侧半线、空心端点、跨行、颜色随变化方向 | 配对只依据记录自身区间 |

不移植：

| 丢弃项 | 理由 |
| --- | --- |
| 边界与枚举校验 | 详情接口已保证越界即 500、取值受枚举约束 |
| 源码切片、文本骨架、渲染自检 | 没有源码视图可回退，自检无消费方 |
| `objects` 与对象配对校验 | 页面不展示对象表；对象差异已由记录 + 区间表达 |
| 多篇选择器与 `key` 认领 | 一路由一篇，编号即身份 |
| 手写消毒函数 | 改用成熟的 HTML 消毒库 |
| 高亮"闪一下"动画 | 仅服务于离线页的可用性补丁，非行为契约 |

### D4. 模块划分：纯函数与 DOM 隔离

`src/diff/` 下除 `render.js` 与 `wires.js` 外全部是纯函数，输入输出都是普通对象/字符串，
用 `node --test`（零额外依赖）直接跑单测，不需要浏览器环境。

`render.js` 负责"正文 → 渲染容器 → 原子 HTML 列表"这一小段必须接触 DOM 的工作；
`wires.js` 负责测量与 SVG。两者都只在 `onMounted` 之后被调用。

行原子拆分的**判定**（某一层子节点是否可拆、拆成几项）保持为纯函数，只吃子节点的最小描述；
真正的节点克隆留在 `render.js`。这样最容易被写错的一段也能在 node 里单测。

### D5. 消毒交给专用库，标记属性改为空格分隔

正文来自外部采集，必须消毒后才能插入 DOM。用手写消毒（后端模板里的做法）等于自己维护一份
安全清单，改用 `dompurify`（允许 `mark`、`class`、`data-*`）。

同时把标记上的记录标识从逗号分隔改为**空格分隔**，这样单个标记就能用 `~=` 精确匹配某个标识
（`data-rids~="12"` 不会误命中 `120`）。

落地修正：最初设想由 `.row:has(mark.hl[data-rids~="12"])` 直接表达选中态，但 CSS 无法拿
容器的 `active-rid` 属性去和后代标记的 `data-rids` 做比较，`:has()` 只能写死具体标识。
因此标记仍保留空格分隔的 `data-rids`（连线与自检按标识查找高亮时要用），选中与悬停改回
原模板的做法：组件在 `activeRid` / 悬停变化时对该记录命中的标记与行切换 `is-active` / `selected`
两个类。行为与设计一致，只是驱动方式由选择器换成了类切换。

### D6. 呈现层：声明式行 + `v-html` 原子

行由 Vue 渲染（`v-for` 行规格，两侧 cell 用 `v-html` 输出原子 HTML），连线仍用命令式测量。

- 放弃的方案：照抄后端的命令式 DOM 构建。它要自己管清空、重建、事件委托，Vue 化收益为零。
- 行只在"换一篇/重载"时重建一次，因此不存在重渲染丢滚动位置的问题；
  `keys` 用行序号，选中态与悬停态只切类、不触发行重建。
- 选中与强调由类切换驱动（见 D5 的落地修正），只有"滚动到第 k 行""测量连线"需要读 DOM。

### D7. 连线测量：一个调度器合并所有触发源

连线在"布局变化"后重算，触发源有四个：挂载完成、行尺寸变化（`ResizeObserver`）、
图片 `load`/`error`、`document.fonts.ready`，外加窗口 `resize`。全部合并进同一个
`scheduleWires()`（微任务去抖、同一帧只画一次），避免多次重复测量。

线段坐标原点取"滚动内容容器的顶"，因此**滚动不触发重算**，连线形状与滚动位置无关。

### D8. 列表态进 URL，不引入 store

`matched / page / size` 写入 query（`?matched=1&page=2&size=50`），从详情返回自然恢复。
不用 Pinia：没有跨路由共享的可变状态，Pinia 只会多一层间接。

### D9. 外壳用 Ant Design Vue，对照区保留手写 CSS

- `ant-design-vue@^4`（cssinjs）+ `unplugin-vue-components` 按需引入（`importStyle: false`），
  只额外引入 `ant-design-vue/dist/reset.css`。
- 根组件挂 `a-config-provider` 的 `darkAlgorithm`，列表页用 `a-table`/`a-select`/`a-tag`/`a-empty`/`a-alert`。
- 对照区（`1fr / 56px / 1fr` 网格、`mark` 样式、连线层）保持手写 CSS：它需要精确控制行高与
  覆盖层，不适合套组件。但配色统一取 antd token（新增/删除/修改分别映射
  `colorSuccess` / `colorError` / `colorWarning`），避免出现两套暗色。

### D10. 详情可进入性只认匹配态

`matched === 1` 才给入口。`status === 'failed'` 但 `matched === 1` 允许进入（此时通常没有对齐与
记录，页面落在降级路径或"两侧一致"分支）。依据：详情接口只以匹配态判定 404。

### D11. API 基址与代理

开发期 `vite.config.js` 配 `server.proxy['/api'] → http://127.0.0.1:8001`（`rewrite` 去掉 `/api`
前缀）。前端统一以 `import.meta.env.VITE_API_BASE ?? '/api'` 拼地址，生产假定同域反向代理。
跨域部署需要后端加 CORS，属于范围外。

### D12. 依赖：`marked` 精确锁 18.2.0

块索引依赖 lexer 的 `token.raw` 语义（`raw` 首尾相接覆盖全文、列表项 `raw` 可逐项累加），
后端内置的正是 18.2.0。`package.json` 里写死 `"marked": "18.2.0"`，不加 `^`。

### D13. 结果列以「记录 → 匹配态 → 状态」三信号判定

`records` 为空不是「无差异」的同义语。真实数据 26 条结论里有 23 条是
`matched=0 / status=completed / records=[]`、参考侧为 `null`——发布侧稿件没有对上任何内部稿件，
业务上读作「疑似未审」。只凭 `records.length === 0` 写「一致」，等于把「没审」谎报成「审过且相同」；
后端对多种成因都返回空数组，因此 `records` 只能回答「有没有差异记录」，不能回答「是否一致」。

判定顺序（先命中者生效）：

| 顺序 | 条件 | 显示 | 依据 |
| --- | --- | --- | --- |
| 1 | 记录非空 | 按方向用中文名报数：新增 a／删除 r／修改 p；方向计数不足时退为 `N 处` | 有数据就报数，脏数据也不说谎；符号不依赖图例就能读懂 |
| 2 | `matched = 0` 或参考侧缺失 | 疑似未审 | 发布侧未匹配到内部稿件 |
| 3 | `matched = 2` | 未完成比对 | 匹配态未知表示对比尚未完成 |
| 4 | `status = pending` | 待核查 | 还没开始 |
| 5 | `status = processing` | 核查中 | 进行中 |
| 6 | `status = failed` | 核查失败 | 跑过但中断 |
| 7 | 其余 | 一致 | 唯一真一致 |

第 4~6 条与状态列的文字重复，这是有意接受的代价：若结果列在「匹配成功 + 失败 + 零记录」时
只看记录数，就会出现「结果=一致、状态=失败」自相矛盾的行。状态列只回答「为什么没有结论」，
结果列回答「结论是什么」——没有结论时唯一可信的答案就是尚未完成的原因。

判定抽成 `src/diff/records.js` 的纯函数 `changeSummary(record)`，返回 `{ tone, parts, text, hint }`：
`tone === 'counts'` 时渲染 `parts`（方向 + 计数，方向有缺失时退为 `text` 的「N 处」），
其余 `tone` 直接渲染 `text`；`hint` 供 `疑似未审`／`未完成比对` 的悬停说明。
计数分支渲染 `parts` 时带上方向中文名（取 `KIND_LABELS`）并按方向配色，不依赖图例就能读懂；
七条分支由 `node --test` 覆盖，模板里不再出现 `total === 0 ? '一致' : …` 这种把语义压进三元表达式的写法。
`summarizeChanges` 保持原职责——只计数，不再兼任「是否一致」的判据。

### D14. 序号与身份分离

列表「编号」改为按页码与条数派生的序号（`(页码 - 1) × 每页条数 + 本页次序`），跨页连续，
与结论编号无关。因此序号 MUST NOT 承担身份：

- 行标识（`row-key`）仍取结论编号，否则翻页或过滤后行状态会串；
- 详情跳转仍以结论编号拼地址，否则会 404；
- 结论编号以 `title` 提示暴露（`结论 #52`），不占列宽但保住可追溯性。

列名同时按业务口径改写：参考侧 → 内部稿件名、发布侧 → 发布稿件名、操作 → 详情；
匹配态列并入结果列后不再单独占位。状态与创建时间保留并排在结果之后——合并后
「已完成」这一信息不再能从结果列读到，出问题时创建时间也是排障的第一线索。

## Risks / Trade-offs

- **marked 版本或 lexer 行为漂移** → 块索引建不起来，页面进入"按块序配对"降级。
  缓解：精确锁版本；降级有顶部提示可观测；验收时比对行数。
- **五条安全判据移植偏差** → 高亮位置偏移或正文结构被破坏。
  缓解：逐条对拍单测（同一正文 + 区间集合与后端结果比对），并用后端生成的离线页做整体对照。
- **对比区性能**：上百行 + 每次测量全量 `getBoundingClientRect`。
  缓解：连线只在布局变化时测一次、不做虚拟滚动、必要时把测量批量收敛到一次 `querySelectorAll`。
  若实测卡顿，优先优化测量而不是引入虚拟滚动（那会破坏单滚动容器与跨行连线）。
- **`v-html` 安全面**：正文来自外部采集，必须经过消毒；`mark` 与 `data-*` 需显式放行，
  否则高亮与联动全部失效（消毒配置错误会静默失效，验收时必须检查高亮处的数量）。
- **antdv 与手写 CSS 的暗色一致性** → 两套变量容易漂移。
  缓解：对照区只从 antd token 取色，不自定义背景与文字色。
- **时间字段时区**：后端 `created_at` 为不带时区的 datetime，前端按原样格式化展示，不做时区换算。
- **列表 `records` 只有元信息**：差异汇总只能给出"新增/删除/修改各几处"，给不出文本，
  这是接口契约的一部分，不在前端补造。

## Migration Plan

1. 安装依赖并配置代理、`unplugin-vue-components`（`pnpm add` 后立即提交 lockfile）。
2. 落地 `src/diff/` 纯函数与单测，先让算法在 node 里跑通（可离线用样例数据）。
3. 落地 `api/` 与路由、`App.vue` 外壳，删除 `stores/counter.js` 与占位内容。
4. 列表页 → 详情页 → 对照区组件。
5. 对照验收：同一结论编号分别用后端离线页与本页渲染，比对行数/单侧行数/连线端点数/高亮处数/卡片摘要。

回滚：整个变更集中在本仓库 `src/`、`vite.config.js`、`package.json`、`index.html`，
撤回该 change 的提交即可回到脚手架；后端无任何改动可回滚。
