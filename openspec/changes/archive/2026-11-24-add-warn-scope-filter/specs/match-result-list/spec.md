# Spec Delta

## ADDED Requirements

### Requirement: 关注集过滤必须与匹配态正交叠加

列表页 MUST 提供一个勾选项，展示文案 MUST 为「仅看疑似未审或有差异」。勾选时列表请求 MUST 携带关注集参数并取其约定值，未勾选时 MUST NOT 携带该参数（等同服务端默认集合）。

关注集的范围 MUST 由服务端定义：勾选后返回哪些结论 MUST 完全取自服务端结果，页面 MUST NOT 用条目的匹配态、差异记录、核查状态等本地字段再筛一遍或另行补齐。勾选项文案是描述性的，MUST NOT 被当成可从条目字段推导出的判定等式；例如参考侧缺失的条目是否属于该集合，MUST 由服务端决定。

关注集与匹配态过滤 MUST 正交叠加：关注集决定范围，匹配态在该范围内继续收窄，两者 MUST 按逻辑与组合，MUST NOT 互斥、MUST NOT 互相覆盖、MUST NOT 规定优先级。勾选项 MUST NOT 改变结果列的既有判定与文案。

切换勾选状态 MUST 回到第一页。勾选状态 MUST 反映在页面地址中并可从中恢复，未勾选时 MUST NOT 写入地址；地址中的取值非法时 MUST 回落为未勾选，MUST NOT 报错或白屏。

关注集与匹配态「未知」的组合 MUST 呈现为空结果而不是失败：页面 MUST 给出说明二者无交集的空态提示，并 MUST 保留勾选项与匹配态过滤可用。

#### Scenario: 默认不勾选

- **WHEN** 使用者打开列表页且地址中不带关注集参数
- **THEN** 勾选项为未勾选，请求不带关注集参数，页面展示全部结论的第一页

#### Scenario: 勾选后只看疑似未审或有差异

- **WHEN** 使用者勾选「仅看疑似未审或有差异」
- **THEN** 请求携带关注集取值并回到第一页，列表只展示未匹配的结论与匹配成功且存在差异记录的结论，总数取服务端返回的值

#### Scenario: 勾选后与匹配态叠加

- **WHEN** 使用者勾选后把匹配态切到「匹配」
- **THEN** 请求同时携带关注集取值与匹配态取值，列表只出现匹配成功且存在差异记录的条目，两侧完全一致的结论不出现

#### Scenario: 关注集与未知匹配态组合为空

- **WHEN** 使用者勾选「仅看疑似未审或有差异」且匹配态为「未知」
- **THEN** 页面显示说明二者无交集的空结果提示，勾选项与匹配态过滤仍可用，页面不报错

#### Scenario: 勾选状态可分享

- **WHEN** 使用者把勾选后的地址交给他人直接打开
- **THEN** 页面以勾选状态按同一条件请求，勾选项呈现为已勾选

#### Scenario: 地址中的关注集取值非法

- **WHEN** 地址中的关注集取值不是服务端约定的取值
- **THEN** 页面按未勾选处理并发起请求，MUST NOT 报错或白屏

#### Scenario: 从详情返回保持勾选

- **WHEN** 使用者以勾选状态进入某条匹配成功结论的详情，然后返回列表
- **THEN** 列表仍处于勾选状态与原页码，不回到默认视图
