# Proposal

## Why

同一个对象在两个页面有两个名字：列表页的列名已经是「发布稿件名 / 内部稿件名」，详情页的对照区却仍叫「参考侧 / 发布侧」。使用者从列表点进详情，需要在脑子里自己做一次术语映射；而详情页内部本身也不统一——表头、单侧行的空侧占位、差异记录卡片三处虽然都写「参考侧/发布侧」，一改就必须一起改，否则同一屏会出现新旧混用。

页头把「结论 #29」放在最显眼的位置同样没有指引价值：结论编号是内部追溯用的，使用者真正关心的是这一页在比哪两篇稿件；编号已经存在于地址中，并从列表页的序号提示可查，没有必要再占页头。

## What Changes

- 对照区表头两条标签由「参考侧 / 发布侧」改为「内部稿件 / 发布稿件」
- 单侧行的空侧占位由「参考侧无对应内容 / 发布侧无对应内容」改为「内部稿件无对应内容 / 发布稿件无对应内容」
- 差异记录卡片每侧标签同步改名（沿用 `SIDE_LABELS` 一处改动即辐射到卡片两侧所有出现位置）
- 详情页头移除可见的「结论 #编号」，保留「← 返回列表」与「坐标版本 vN」
- 列表页「疑似未审」的依据说明由「发布侧未匹配到内部稿件…」改为「发布稿件未匹配到内部稿件…」，消掉同一句话里新旧词混用
- 明确不改动：术语之外的布局与间距、标题分列、逐行对齐、高亮、连线、记录卡定位与游标、列表分页与过滤、返回列表的条件恢复；结论编号作为追溯手段保留在地址与列表序号提示中

无 **BREAKING** 变更：接口、数据结构、路由与跳转行为均不变。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `match-result-detail`：新增「两侧标签必须使用统一稿件术语」与「页头必须保留返回与版本、不展示结论编号」两条行为要求
- `match-result-list`：「疑似未审」等结果列依据说明的用词必须沿用同一套稿件术语

## Impact

- `src/components/diff/DiffWorkspace.vue`：对照区表头两处硬编码标签
- `src/components/diff/DiffRow.vue`：`refLabel` / `inpLabel` 默认值，即单侧行的空侧占位文案
- `src/diff/constants.js`：`SIDE_LABELS`，经 `RecordCard.vue` 渲染记录卡每侧标签
- `src/views/MatchResultDetail.vue`：页头的「结论 #编号」
- `src/diff/records.js`：「疑似未审」的悬停提示文案
- 测试：现有断言不比对这几个字面量（仅测试标题与注释中出现），改动不改变任何用例的期望值，但需跑一遍 `pnpm test` 回归
- 无接口、依赖、构建配置改动；不涉及后端
