# Spec Delta

## ADDED Requirements

### Requirement: 关键词检索必须由服务端执行并与其它过滤叠加

列表页 MUST 提供一个关键词输入控件，把使用者输入的检索词作为服务端列表接口的关键词参数发送，由服务端在发布侧与内部侧的稿件标题上做子串匹配；两侧任一命中即返回，匹配 MUST 大小写不敏感。

关键词 MUST 参与服务端分页与计数：页面 MUST NOT 在本地对条目做二次筛选、二次排序或重新计算总数，总数 MUST 取服务端返回值。

提交前 MUST 去掉检索词首尾空白；去空白后为空串时 MUST NOT 携带关键词参数。检索词长度 MUST 限制在后端上限 128 字符以内：控件 MUST 阻止输入超出上限，地址中超出上限的取值 MUST 被截断后再作为条件使用，MUST NOT 因超长取值导致请求失败。

关键词 MUST 与关注集、匹配态按逻辑与叠加，MUST NOT 互斥、MUST NOT 规定优先级。

改变关键词 MUST 回到第一页。输入过程中 MUST 防抖，且地址更新 MUST 采用替换而非新增历史记录，使连续输入不会把浏览器历史塞满。

#### Scenario: 按稿件名检索

- **WHEN** 使用者输入「关于某某的通知」并停止输入
- **THEN** 页面以该关键词、`pageNum=0` 请求列表，展示两侧标题任一命中的条目，并显示服务端给出的总数

#### Scenario: 检索词首尾带空白

- **WHEN** 使用者输入的检索词在去空白后非空
- **THEN** 请求携带去空白后的检索词，输入框仍显示使用者输入的原文

#### Scenario: 清空检索词

- **WHEN** 使用者把检索词清空或只留下空白
- **THEN** 请求不再携带关键词参数，列表回到不带关键词的第一页

#### Scenario: 关键词与关注集叠加

- **WHEN** 使用者在勾选「仅看疑似未审或有差异」的同时输入检索词
- **THEN** 请求同时携带关键词与关注集取值，返回条目完全由服务端交集决定，页面不做本地补齐或排除

#### Scenario: 直接打开带关键词的地址

- **WHEN** 使用者打开地址中带有合法关键词的列表页
- **THEN** 输入框回显该关键词，页面按该关键词请求第一页

#### Scenario: 地址中的关键词超长

- **WHEN** 地址中的关键词长度超过 128 字符
- **THEN** 页面按前 128 字符请求并回显同样截断后的值，不出现错误提示

#### Scenario: 连续输入不刷历史

- **WHEN** 使用者连续输入多个字符后点击返回
- **THEN** 不会因逐字符的地址更新而需要逐字符回退

#### Scenario: 从详情返回保留关键词

- **WHEN** 使用者以带关键词的视图进入某条结论的详情，然后返回列表
- **THEN** 列表仍带同一关键词与原页码

## MODIFIED Requirements

### Requirement: 列表必须以服务端分页与三态过滤为准

列表 MUST 通过后端结论列表接口取数，并原样使用服务端返回的总数与条目顺序，MUST NOT 在前端重新排序、重新去重或按业务键折叠。列表条目 MUST 取自响应中的条目列表字段（`rows`），总数 MUST 取自响应中的总数字段（`total`）。

列表页 MUST NOT 提供匹配态过滤控件，缺省视图 MUST 为全部匹配态。匹配态 MUST 仍可从页面地址读取：地址中的匹配态取值为「匹配 / 不匹配 / 未知」三种约定值之一时 MUST 原样作为参数发给服务端，取值非法或缺失时 MUST 按全部匹配态处理并不携带该参数。移除控件 MUST NOT 改变匹配态的请求语义与合法取值集合，使后续恢复控件时无需改造状态层。

分页 MUST 以「页码 + 每页条数」表达：请求参数 MUST 使用后端约定的 `pageNum` 与 `pageSize`，其中 `pageNum` 从 0 起（页码 1 对应 `pageNum` 0），MUST NOT 再发送偏移量参数。每页条数 MUST 有上限，超出上限的请求 MUST 被客户端拒绝或收敛到上限而不是静默截断；`pageNum` MUST 不为负。切换关键词或关注集时 MUST 回到第一页。

总数 MUST 取自服务端返回的去重与过滤后条数，MUST NOT 由当前页条目数推算。

#### Scenario: 默认进入列表

- **WHEN** 使用者打开列表页且未携带任何过滤条件
- **THEN** 页面以 `pageNum=0` 与默认每页条数请求，不带匹配态参数，按服务端默认顺序展示第一页条目，并显示服务端给出的总数

#### Scenario: 页面不再出现匹配态控件

- **WHEN** 使用者打开列表页
- **THEN** 控制区只有关键词输入与「仅看疑似未审或有差异」勾选项，没有匹配态下拉或其它匹配态入口

#### Scenario: 切换匹配态

- **WHEN** 使用者通过重新打开或手改地址，把匹配态从「全部」改为某个约定取值，或从某个约定取值改为「全部」
- **THEN** 页面以新取值请求，地址未指定页码时从第一页开始展示，控制区不出现对应控件

#### Scenario: 地址中带匹配态

- **WHEN** 使用者打开地址中带匹配态为「匹配」的列表页（例如旧书签或他人分享的链接）
- **THEN** 请求携带该匹配态取值，页面只展示匹配态的条目，控制区不出现对应控件

#### Scenario: 地址中的匹配态非法

- **WHEN** 地址中的匹配态取值不属于三种约定值
- **THEN** 页面按全部匹配态请求，不报错、不白屏

#### Scenario: 翻到最后一页

- **WHEN** 去重与过滤后共 25 条，使用者翻到第 3 页（每页 10 条）
- **THEN** 页面请求 `pageNum=2`、`pageSize=10`，只展示 5 条，总数仍显示 25

#### Scenario: 每页条数超出上限

- **WHEN** 页面选定的每页条数超过后端上限 200
- **THEN** 请求中的 `pageSize` 被收敛到 200，页面不因参数非法而失败

#### Scenario: 切换过滤条件回到第一页

- **WHEN** 使用者停在第 3 页时改变关键词或切换关注集勾选
- **THEN** 请求的 `pageNum` 回到 0

### Requirement: 关注集过滤必须与匹配态正交叠加

列表页 MUST 提供一个勾选项，展示文案 MUST 为「仅看疑似未审或有差异」。勾选时列表请求 MUST 携带关注集参数并取其约定值，未勾选时 MUST NOT 携带该参数（等同服务端默认集合）。

关注集的范围 MUST 由服务端定义：勾选后返回哪些结论 MUST 完全取自服务端结果，页面 MUST NOT 用条目的匹配态、差异记录、核查状态等本地字段再筛一遍或另行补齐。勾选项文案是描述性的，MUST NOT 被当成可从条目字段推导出的判定等式；例如参考侧缺失的条目是否属于该集合，MUST 由服务端决定。

关注集与匹配态过滤 MUST 正交叠加：关注集决定范围，匹配态在该范围内继续收窄，两者 MUST 按逻辑与组合，MUST NOT 互斥、MUST NOT 互相覆盖、MUST NOT 规定优先级。勾选项 MUST NOT 改变结果列的既有判定与文案。

勾选状态的来源 MUST 按下列优先级确定：地址中显式带关注集取值时以地址为准；地址未带时以浏览器本地缓存为准；两者都没有时视为未勾选。勾选状态 MUST 写入本地缓存，使下次不带条件打开列表页时恢复上次的选择。缓存 MUST 只由使用者的显式勾选或取消写入，MUST NOT 因页面加载、地址恢复或请求结果而回写，避免打开他人分享的链接时改掉自己的偏好。

未勾选时 MUST NOT 把关注集取值写入地址。地址中的取值非法时 MUST 回落为未勾选，MUST NOT 报错或白屏，且 MUST NOT 因此改写缓存。本地缓存不可读或不可写时（例如隐私模式或被禁用）MUST 降级为「未勾选」工作，MUST NOT 阻塞首屏或抛出错误。

切换勾选状态 MUST 回到第一页。

关注集与匹配态「未知」的组合 MUST 呈现为空结果而不是失败：页面 MUST 给出说明二者无交集的空态提示，并 MUST 保留勾选项与关键词输入可用。

#### Scenario: 默认不勾选

- **WHEN** 使用者首次打开列表页，地址不带关注集参数，本地也没有缓存
- **THEN** 勾选项为未勾选，请求不带关注集参数，页面展示全部结论的第一页

#### Scenario: 勾选后只看疑似未审或有差异

- **WHEN** 使用者勾选「仅看疑似未审或有差异」
- **THEN** 请求携带关注集取值并回到第一页，列表只展示未匹配的结论与匹配成功且存在差异记录的结论，总数取服务端返回的值

#### Scenario: 勾选后与匹配态叠加

- **WHEN** 使用者勾选「仅看疑似未审或有差异」，并以带匹配态为「匹配」的地址打开列表
- **THEN** 请求同时携带关注集取值与匹配态取值，列表只出现匹配成功且存在差异记录的条目，两侧完全一致的结论不出现

#### Scenario: 记住上次的选择

- **WHEN** 使用者勾选后关闭页面，稍后不带条件重新打开列表页
- **THEN** 勾选项为已勾选，页面直接按关注集请求

#### Scenario: 取消勾选也会被记住

- **WHEN** 使用者取消勾选后关闭页面，稍后不带条件重新打开
- **THEN** 勾选项为未勾选，页面按全部结论请求

#### Scenario: 地址优先于本地缓存

- **WHEN** 本地缓存为未勾选，使用者打开了一个带关注集取值的分享地址
- **THEN** 页面按勾选状态请求，而不是按本地缓存回落为未勾选

#### Scenario: 分享地址不污染本地偏好

- **WHEN** 使用者打开了一个带关注集取值的分享地址，未做任何勾选操作就离开，随后不带条件重新打开列表页
- **THEN** 页面恢复使用者自己此前的选择，而不是被动接受分享地址里的取值

#### Scenario: 地址中的关注集取值非法

- **WHEN** 地址中的关注集取值不是服务端约定的取值
- **THEN** 页面按未勾选处理并发起请求，不报错、不白屏，本地缓存保持原值

#### Scenario: 本地缓存不可用

- **WHEN** 浏览器禁止访问本地缓存
- **THEN** 页面按未勾选工作，列表正常加载，不出现错误提示

#### Scenario: 关注集与未知匹配态组合为空

- **WHEN** 使用者以带关注集取值且匹配态为「未知」的地址直接打开列表页
- **THEN** 页面显示说明二者无交集的空结果提示，勾选项与关键词输入仍可用，页面不报错

#### Scenario: 勾选状态可分享

- **WHEN** 使用者把勾选后的地址交给他人直接打开
- **THEN** 页面以勾选状态按同一条件请求，勾选项呈现为已勾选

#### Scenario: 从详情返回保持勾选

- **WHEN** 使用者以勾选状态进入某条匹配成功结论的详情，然后返回列表
- **THEN** 列表仍处于勾选状态与原页码，不回到默认视图

### Requirement: 筛选与分页状态必须可分享且可回退

当前关键词、过滤条件与页码 MUST 反映在页面地址中，使地址可被直接分享，并让从详情页返回列表时恢复原来的关键词、过滤与页码。

直接以带条件的地址打开页面时，MUST 按地址中的条件发起请求；地址中的条件非法或越界时，MUST 退回到该条件的合法缺省值，MUST NOT 报错或白屏。关注集取值的缺省来源 MUST 按关注集要求中的优先级处理（地址优先，其次本地缓存）。

地址 MUST NOT 携带缺省值：全部匹配态、未勾选、第一页、默认每页条数、空关键词一律不写入地址。地址中出现的多余或非法键 MUST 被规范化移除，MUST NOT 残留为不可见状态。

#### Scenario: 从详情返回

- **WHEN** 使用者带着关键词、勾选状态与第 2 页进入详情，然后返回列表
- **THEN** 列表仍处于同一关键词、同一勾选状态与第 2 页，不回到默认视图

#### Scenario: 分享地址

- **WHEN** 另一个使用者直接打开带有过滤与页码的地址
- **THEN** 页面按该条件请求并展示同样的视图

#### Scenario: 地址中的页码越界

- **WHEN** 地址中的页码超过了当前条件下的总页数
- **THEN** 页面回到第一页展示，且不报错

#### Scenario: 缺省值不写入地址

- **WHEN** 使用者清空关键词、取消勾选并回到第一页
- **THEN** 地址中不再包含关键词、关注集与页码参数

### Requirement: 加载、空结果与失败必须显式呈现且可重试

列表在请求进行中 MUST 呈现加载状态；请求失败 MUST 呈现失败原因与重试入口，MUST NOT 展示为「没有数据」。

过滤后没有任何条目时 MUST 呈现空结果提示，MUST 保留关键词输入与关注集勾选项，使使用者可以改回其它条件。空结果提示 MUST 区分「关键词无命中」「关注集与未知匹配态无交集」与「一般无符合条件条目」三种情况，MUST NOT 用同一句话覆盖。

#### Scenario: 接口失败

- **WHEN** 列表请求返回错误状态
- **THEN** 页面显示错误提示与重试按钮，重试后重新发起同条件请求

#### Scenario: 过滤后为空

- **WHEN** 以「未知」过滤且没有任何条目
- **THEN** 页面显示空结果提示，过滤控件仍可用

#### Scenario: 关键词无命中

- **WHEN** 使用者输入的关键词在当前条件下没有任何条目
- **THEN** 页面显示区别于其它空态的结果提示，关键词输入与勾选项仍可用，使用者可直接改写或清空关键词
