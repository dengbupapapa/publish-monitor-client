# Proposal

## Why

列表页页头把「稿件核查结论」当成大标题，下面再跟一句「只读视图：按服务端分页与过滤列出对比结果，点开可查看两侧逐行对照。」两行文字占着首屏最高的视觉位置，却几乎不传递信息：这一页是什么、怎么用，看表头和两个控件就能明白；而同样的标题信息在浏览器标签里已经有一份。详情页的页头也早已收敛为「返回入口 + 坐标版本」，列表页保留一个孤立的大标题反而让两个页面的页头不成体系。

真正需要被一眼找到的是关键词检索与「仅看疑似未审或有差异」勾选，它们不该被整页说明文字压到第二视觉层级。

## What Changes

- 移除列表页页头的大标题「稿件核查结论」，及其下一整页说明句「只读视图：按服务端分页与过滤列出对比结果，点开可查看两侧逐行对照。」
- 页头收缩为单行控制条：关键词检索与「仅看疑似未审或有差异」勾选项**一个都不移除**，保持原位右对齐；宽度、间距、防抖、缓存与请求行为全部不变
- 一并清理只服务于这两行文字的 scoped 样式（`.page-head h1`、`.page-head p`），并把页头对齐方式由 `space-between` 收敛为右对齐——只剩一个子元素后 `space-between` 已不产生任何布局作用，留着会误导后来者
- 明确不改动：筛选与分页状态、地址可分享与可回退、空态与失败文案、表格列与详情入口、关注集的地址/缓存优先级；`index.html` 的浏览器标签标题与 README 里的项目说明同样保留

无 **BREAKING** 变更：接口、路由、地址参数与跳转行为均不变。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `match-result-list`: 新增「页头只保留过滤控件、不展示页面标题与整页说明」的行为要求，并把控制区右对齐与「控件不得因移除文案而减少」固定下来

## Impact

- `src/views/MatchResultList.vue`：`<header class="page-head">` 内的 `h1`、`p` 及包住它们的空 `div`；同文件 `<style scoped>` 中的 `.page-head` 对齐规则与 `.page-head h1` / `.page-head p` 两条规则
- 不变：`src/api/`、`src/stores/listPrefs.js`、`src/router/index.js`、`index.html`、`README.md`、`src/views/MatchResultDetail.vue`
- 测试：现有用例没有断言这两句文案，改动不改变任何期望值，仅需跑一遍回归
- 无依赖、构建配置或后端改动
