# Design

## Context

`ScheduledTaskList.vue` 当前直接渲染 `record.cron`，而 `CronInput.vue` 已通过 `cronText.js` 中的 `describeCron` 展示中文描述。现有 `rows` 计算属性已为表格派生序号，可同时承载展示用字段；项目使用 `node:test` 验证 `cronText.js` 纯函数，没有 Vue 组件测试框架。具体行为要求见 `specs/scheduled-task-list/spec.md`。

## Goals / Non-Goals

**Goals:**

- 以最小改动复用现有中文转换能力，并保证无效历史数据不会中断表格渲染。
- 让展示逻辑可用现有 `node:test` 直接覆盖。
- 保持表格省略展示、原始表达式查看和表单既有编辑体验。

**Non-Goals:**

- 不引入通用 Cron 展示组件、组件测试框架、国际化框架或新依赖。
- 不修改 Cron 点选器、校验规则、接口数据结构和服务端错误转换规则。

## Decisions

### 1. 在现有文本工具中提供安全转换，而不是新增组件

在 `cronText.js` 中基于 `describeCron` 增加安全转换函数：成功时返回中文描述，转换抛出异常时返回原始表达式，空值仍返回空文本。`ScheduledTaskList.vue` 使用该函数生成展示值。

选择这一方案是因为中文转换及其异常边界同属现有纯函数模块，能够直接补充 `node:test` 覆盖。新增 Vue 组件只会包装一次文本转换，不能解决解析异常，也会增加不必要的状态和样式边界。仅在转换前调用 `isValidCron` 不足以作为保障，因为本地校验器与 `cronstrue` 的语法接受范围可能不同，因此必须捕获实际转换异常。

### 2. 在表格行派生阶段计算一次中文描述

在现有 `rows` 映射中附加展示用 `cronDescription`，单元格不再直接显示 `record.cron`，也不再使用等宽字体展示中文。空描述显示现有空占位。

列标题改为「任务规则」，保留 `ellipsis`。单元格原生 `title` 在有效规则时组合完整中文描述与原始表达式；无效规则回退为原始表达式，空值不拼接无意义提示。继续采用项目已有的原生悬浮提示方式，不引入额外浮层组件。可适当增加该列宽度以减少常见中文规则的省略，但不改变其他列和操作列行为。

### 3. 只统一客户端生成的字段名称与默认提示

`ScheduledTaskForm.vue` 的共享字段标签改为「任务规则」，同时覆盖创建和编辑。`CronInput.vue` 的无效规则提示，以及 `scheduledTasks.js` 中本地校验和无服务端文案时的默认 Cron 错误提示，同步改用「任务规则」。

只读区域的「表达式」标签和「五段式 cron」技术格式说明保留，避免混淆中文业务名称与实际提交格式。`classifyScheduleError` 收到服务端 `message` 时仍原样返回，不改写服务端业务文案，也不改变错误字段归位。

### 4. 按纯函数与现有测试习惯验证

- 在 `cronText.test.js` 覆盖安全转换的有效表达式、无效表达式和空值。
- 在 `scheduledTasks.test.js` 更新客户端默认错误文案断言，并保留服务端自定义错误原样展示的断言。
- 运行完整 `npm test` 与 `npm run build`。
- 通过页面检查常见规则、长规则、无效历史规则，以及新建和编辑表单；确认保存载荷仍使用原始 `cron` 字符串。

## Risks / Trade-offs

- [复杂 Cron 的中文描述可能很长，增加表格拥挤] → 保留单元格省略并适度调整列宽，悬浮提示提供完整描述和原始表达式。
- [本地校验通过但中文转换库无法解析] → 安全转换直接捕获转换异常并回退原始表达式，避免整页渲染失败。
- [展示层派生字段可能被误提交] → 派生字段只存在于表格行视图模型，创建和编辑载荷继续由既有表单数据构造，不回写任务记录。

## Migration Plan

无需数据或接口迁移。该变更仅影响前端展示和默认文案，部署后立即可用；如需回滚，还原对应前端文件即可，不涉及数据补偿。
