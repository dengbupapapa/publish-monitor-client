# Design

## Context

见 proposal.md。现状与约束：

- 列表页 `src/views/MatchResultList.vue` 把过滤与分页状态全部折叠在页面地址里，并用一个「规范化 watcher」把多余/非法键改写回规范形态（scope、matched、keyword、page、size 五个键）。
- 列表请求由 `src/api/matchResults.js` 的 `buildListQuery` 拼装，`matched` / `scope` / `keyword` 的上限与缺省规则都在这一层收敛。
- 后端已提供 `GET /diff-run-options/job-types`（无参数，取 `task_run` 出现过的类型，`label` 为最新流程名，缺失回退 `value`）与 `GET /diff-run-options/biz-scopes?job_type=`（`label` 为业务名称、`value` 为业务编号，按 `label` 去重保留最新编号）。`/match-results` 已接受 `job_type` 与 `biz_scope` 等值过滤。
- `src/views/ScheduledTaskList.vue` 已有「下拉筛选 + 选项字典失败不阻塞列表」的先例，但它用的是注册表字典 `/job-types`，语义与本次的「运行记录字典」不同，不能直接复用其取数函数。

## Goals / Non-Goals

**Goals:**

- 以最小改动把两个运行维度下拉接到既有地址状态模型上，保持可分享、可回退、缺省不写地址。
- 单向级联（类型 → 账号）在网络失败、竞态与地址恢复三种情况下都有确定行为。

**Non-Goals:**

- 不改后端，不新增接口。
- 不引入前端缓存或全局状态；选项只存在页面内存里。
- 不做反向级联，不引入 `biz_type` / `biz_name` 下拉。

## Decisions

### 选项来源：运行记录字典，而非注册表

任务类型用 `/diff-run-options/job-types`，账号用 `/diff-run-options/biz-scopes`。注册表字典 `/job-types` 只含当前注册类型，与「历史结论仍可按已下线类型查询」的后端语义冲突；账号则根本没有注册表。代价是选项可能包含没有任何结论的运行，选中后为空——由空态文案承接。

### 账号筛选值取 `label`（业务名称），不取 `value`（编号）

`/match-results` 的 `biz_scope` 按名称等值匹配，编号对应另一个参数 `biz_scope_id`。后端选项按名称聚合、同名只保留最新编号，说明名称才是账号的稳定身份：同一账号换过编号时，按名称能命中全部历史结论，按编号只能命中最新那一段。被放弃的替代方案是按 `biz_scope_id` 精确匹配，语义更「准」但会漏历史数据，且需要额外的编号参数。

### 单向级联，且失效账号在新选项返回后才清空

`job-types` 不接收参数（后端即如此），`biz-scopes` 接收 `job_type`。切换任务类型时，先取回新的账号选项，再判断当前账号是否仍在其中：不在才清空并回第一页，在则保留。替代方案是切换类型时无条件清空账号，实现更短，但会把「两个类型下都存在」的账号选择无故丢弃。

顺序必须串行，否则会先用旧账号请求一次列表、再用新账号请求第二次，出现闪烁与多余请求。

### 选项加载与列表加载解耦

- 任务类型选项在页面挂载时拉取一次，之后不再变（无反向级联）。
- 账号选项随 `job_type` 变化拉取，使用独立的请求序号与 `AbortController`，防止旧级联结果覆盖新结果。
- 选项请求失败时保留上一次成功的选项；从未成功过则视为空列表，两个下拉只剩「全部」。列表请求不受影响。
- 选项不缓存、不轮询：接口只读且足够便宜，页面停留期间新增的运行不会实时反映到下拉，属可接受的新鲜度。

### 地址状态扩展为七个键

在既有五个键（scope、matched、keyword、page、size）基础上加入 `job_type`、`biz_scope`：

- 归一：`job_type` 去空白并按 32 字符截断，账号名称按 128 字符截断；空串表示「全部」，不写地址。
- 「规范化 watcher」的比对键集合同步扩到七个，否则新增键既纠正不了也保不住。
- 账号在地址中存在但选项里没有（例如选项接口失败、或手改地址）时，下拉需要回显该原始值而不是吞掉它；这要求选项列表按「地址值 + 接口值」合并，避免选中值不可见。

### 页头顺序与空态

页头控件顺序定为「任务类型 → 账号 → 关键词 → 勾选项」，与筛选的粗粒度到细粒度一致。空态在既有分支之后新增「运行维度条件无命中」，仅当 `job_type` 或 `biz_scope` 有值且前面分支都不命中时出现。

## Risks / Trade-offs

- [选项包含无结论的运行，选中必空] → 新增空态文案点明是条件组合无结果，引导改选；不在前端用条目的运行字段补筛（列表行并不携带这些字段）。
- [地址中的账号不在选项内时下拉显示异常] → 选项构造时把地址值并入候选（无匹配标签时以原值展示），保证回显可见；发请求仍以地址值为准。
- [切换类型时列表先闪一次旧结果] → 级联流程串行：先取选项、再决定是否清账号、最后取列表，中间不并发请求列表。
- [后端接口未部署时两个下拉不可用] → 降级为只有「全部」，列表按既有条件正常工作，不出现错误页。
- [同名账号在选项里只有一个（后端按名称去重）] → 与筛选口径一致，不构成风险；`value` 仅用于展示兜底，不参与筛选。

## Migration Plan

纯前端改动，无数据迁移。后端接口已存在，客户端先于/后于后端发布都可用（未就绪时降级）。回滚只需移除控件与两个参数；旧地址里的 `job_type` / `biz_scope` 会被规范化 watcher 自动移除，不会留下不可见状态。

## Open Questions

- 账号较多时是否需要给下拉加可搜索输入。属于交互增强，不影响接口、规格与任务拆分，可后置。
