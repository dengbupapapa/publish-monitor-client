# Spec Delta

## ADDED Requirements

### Requirement: 运行维度筛选必须提供任务类型与账号两个下拉

列表页页头 MUST 提供两个下拉筛选：任务类型（请求参数 `job_type`）与账号（请求参数 `biz_scope`）。两者的缺省取值 MUST 均为「全部」，「全部」表示不携带对应请求参数。

两个下拉的选项 MUST 取自服务端的运行记录选项接口，而不是流程类型注册表：任务类型选项 MUST 覆盖运行记录里实际出现过的类型（含已从注册表下线的历史类型）；账号选项 MUST 覆盖运行记录里实际出现过的业务名称。任务类型的展示名 MUST 取服务端返回的 `label`，缺失时 MUST 回退展示其 `value`。

账号选项 MUST 随已选任务类型级联：任务类型为「全部」时 MUST 列出全部账号；选定某个任务类型时 MUST 只列出该类型下出现过的账号。任务类型选项 MUST NOT 因已选账号而收窄（不提供反向级联）。级联后已选账号若不在新选项中，页面 MUST 清空账号条件并回到第一页后再取数。

账号筛选值 MUST 使用选项的展示名（`label`，即业务名称）作为 `biz_scope` 参数发送，MUST NOT 使用选项的 `value`（业务编号）。两个运行维度条件 MUST 与关键词、关注集、匹配态按逻辑与叠加，结果 MUST 完全取自服务端，页面 MUST NOT 在本地二次筛选。

切换任务类型或账号 MUST 回到第一页。选项加载失败 MUST NOT 阻塞列表：页面 MUST 保留上一次成功加载的选项，首屏加载失败时两个下拉 MUST 只保留「全部」，列表按当前条件正常取数。

两个参数的长度上限 MUST 与服务端一致：`job_type` 为 32 字符，账号名称为 128 字符；超长取值 MUST 被截断后再使用，MUST NOT 因超长导致请求失败。

#### Scenario: 默认均为全部

- **WHEN** 使用者打开列表页且地址不带这两个参数
- **THEN** 两个下拉均显示「全部」，列表请求不携带 `job_type` 与 `biz_scope`

#### Scenario: 选择任务类型后级联账号选项

- **WHEN** 使用者把任务类型从「全部」改为某个具体类型
- **THEN** 列表请求携带该 `job_type` 并回到第一页，账号下拉只列出该类型下出现过的账号

#### Scenario: 选择账号发送业务名称

- **WHEN** 使用者选择某个账号选项
- **THEN** 列表请求携带 `biz_scope`，其取值为该选项的展示名（业务名称），而不是业务编号，并回到第一页

#### Scenario: 级联后清空失效账号

- **WHEN** 已选账号在当前任务类型下不存在，使用者又切换了任务类型
- **THEN** 页面清空账号条件、回到第一页，并以仅带新任务类型的条件取数

#### Scenario: 任务类型选项不受账号影响

- **WHEN** 使用者先选定某个账号，再查看任务类型下拉
- **THEN** 任务类型选项仍为全量，不因已选账号而减少

#### Scenario: 历史类型仍可作为选项

- **WHEN** 某任务类型已从流程注册表下线，但运行记录里仍有该类型的结论
- **THEN** 任务类型下拉仍列出该类型，使用者选中后请求携带该 `job_type`

#### Scenario: 选项加载失败不阻塞列表

- **WHEN** 选项接口请求失败
- **THEN** 两个下拉只保留「全部」或沿用上次成功的选项，列表仍按当前条件正常加载，页面不出现错误白屏

#### Scenario: 与其它条件叠加

- **WHEN** 使用者同时选定任务类型、账号，并输入关键词或勾选关注集
- **THEN** 请求同时携带全部条件，返回条目完全由服务端交集决定，页面不做本地补齐或排除

## MODIFIED Requirements

### Requirement: 列表必须以服务端分页与三态过滤为准

列表 MUST 通过后端结论列表接口取数，并原样使用服务端返回的总数与条目顺序，MUST NOT 在前端重新排序、重新去重或按业务键折叠。列表条目 MUST 取自响应中的条目列表字段（`rows`），总数 MUST 取自响应中的总数字段（`total`）。

列表页 MUST NOT 提供匹配态过滤控件，缺省视图 MUST 为全部匹配态。匹配态 MUST 仍可从页面地址读取：地址中的匹配态取值为「匹配 / 不匹配 / 未知」三种约定值之一时 MUST 原样作为参数发给服务端，取值非法或缺失时 MUST 按全部匹配态处理并不携带该参数。移除控件 MUST NOT 改变匹配态的请求语义与合法取值集合，使后续恢复控件时无需改造状态层。

分页 MUST 以「页码 + 每页条数」表达：请求参数 MUST 使用后端约定的 `pageNum` 与 `pageSize`，其中 `pageNum` 从 0 起（页码 1 对应 `pageNum` 0），MUST NOT 再发送偏移量参数。每页条数 MUST 有上限，超出上限的请求 MUST 被客户端拒绝或收敛到上限而不是静默截断；`pageNum` MUST 不为负。切换关键词、关注集、任务类型或账号时 MUST 回到第一页。

总数 MUST 取自服务端返回的去重与过滤后条数，MUST NOT 由当前页条目数推算。

#### Scenario: 默认进入列表

- **WHEN** 使用者打开列表页且未携带任何过滤条件
- **THEN** 页面以 `pageNum=0` 与默认每页条数请求，不带匹配态参数，按服务端默认顺序展示第一页条目，并显示服务端给出的总数

#### Scenario: 页面不再出现匹配态控件

- **WHEN** 使用者打开列表页
- **THEN** 控制区只有关键词输入、任务类型下拉、账号下拉与「仅看疑似未审或有差异」勾选项，没有匹配态下拉或其它匹配态入口

#### Scenario: 切换匹配态

- **WHEN** 使用者通过重新打开或手改地址，把匹配态从「全部」改为某个约定取值，或从某个约定取值改为「全部」
- **THEN** 页面以新取值请求，地址未指定页码时从第一页开始展示，控制区不出现对应控件

#### Scenario: 地址中带匹配态

- **WHEN** 使用者打开地址中带匹配态为「匹配」的列表页（例如旧书签或他人分享的链接）
- **THEN** 请求携带该匹配态取值，页面只展示匹配态的条目，控制区不出现对应控件

#### Scenario: 地址中的匹配态非法

- **WHEN** 地址中的匹配态取值不属于三种约定值
- **THEN** 页面按全部匹配态请求，不报错、不白屏

#### Scenario: 翻到最后一页

- **WHEN** 去重与过滤后共 25 条，使用者翻到第 3 页（每页 10 条）
- **THEN** 页面请求 `pageNum=2`、`pageSize=10`，只展示 5 条，总数仍显示 25

#### Scenario: 每页条数超出上限

- **WHEN** 页面选定的每页条数超过后端上限 200
- **THEN** 请求中的 `pageSize` 被收敛到 200，页面不因参数非法而失败

#### Scenario: 切换过滤条件回到第一页

- **WHEN** 使用者停在第 3 页时改变关键词、切换关注集勾选，或改变任务类型、账号
- **THEN** 请求的 `pageNum` 回到 0

### Requirement: 筛选与分页状态必须可分享且可回退

当前关键词、任务类型、账号、过滤条件与页码 MUST 反映在页面地址中，使地址可被直接分享，并让从详情页返回列表时恢复原来的关键词、运行维度条件、过滤与页码。

直接以带条件的地址打开页面时，MUST 按地址中的条件发起请求；地址中的条件非法或越界时，MUST 退回到该条件的合法缺省值，MUST NOT 报错或白屏。关注集取值的缺省来源 MUST 按关注集要求中的优先级处理（地址优先，其次本地缓存）。

地址 MUST NOT 携带缺省值：全部匹配态、未勾选、任务类型为「全部」、账号为「全部」、第一页、默认每页条数、空关键词一律不写入地址。地址中出现的多余或非法键 MUST 被规范化移除，MUST NOT 残留为不可见状态。地址中的任务类型与账号取值超长时 MUST 截断后再作为条件使用，MUST NOT 因超长导致请求失败。

#### Scenario: 从详情返回

- **WHEN** 使用者带着关键词、运行维度条件、勾选状态与第 2 页进入详情，然后返回列表
- **THEN** 列表仍处于同一关键词、同一任务类型、同一账号、同一勾选状态与第 2 页，不回到默认视图

#### Scenario: 分享地址

- **WHEN** 另一个使用者直接打开带有过滤与页码的地址
- **THEN** 页面按该条件请求并展示同样的视图

#### Scenario: 直接打开带运行维度条件的地址

- **WHEN** 使用者打开地址中带有任务类型与账号的列表页
- **THEN** 两个下拉回显地址中的取值，账号选项按该任务类型级联，页面按该条件请求第一页

#### Scenario: 地址中的页码越界

- **WHEN** 地址中的页码超过了当前条件下的总页数
- **THEN** 页面回到第一页展示，且不报错

#### Scenario: 缺省值不写入地址

- **WHEN** 使用者清空关键词、取消勾选、把任务类型与账号都改回「全部」并回到第一页
- **THEN** 地址中不再包含关键词、关注集、任务类型、账号与页码参数

#### Scenario: 地址中的运行维度取值超长

- **WHEN** 地址中的任务类型超过 32 字符或账号名称超过 128 字符
- **THEN** 页面按截断后的取值作为条件请求，不出现错误提示

### Requirement: 加载、空结果与失败必须显式呈现且可重试

列表在请求进行中 MUST 呈现加载状态；请求失败 MUST 呈现失败原因与重试入口，MUST NOT 展示为「没有数据」。

过滤后没有任何条目时 MUST 呈现空结果提示，MUST 保留关键词输入、两个运行维度下拉与关注集勾选项，使使用者可以改回其它条件。空结果提示 MUST 区分「关键词无命中」「关注集与未知匹配态无交集」「运行维度条件无命中」与「一般无符合条件条目」四种情况，MUST NOT 用同一句话覆盖。

#### Scenario: 接口失败

- **WHEN** 列表请求返回错误状态
- **THEN** 页面显示错误提示与重试按钮，重试后重新发起同条件请求

#### Scenario: 过滤后为空

- **WHEN** 以「未知」过滤且没有任何条目
- **THEN** 页面显示空结果提示，过滤控件仍可用

#### Scenario: 关键词无命中

- **WHEN** 使用者输入的关键词在当前条件下没有任何条目
- **THEN** 页面显示区别于其它空态的结果提示，关键词输入与勾选项仍可用，使用者可直接改写或清空关键词

#### Scenario: 运行维度条件无命中

- **WHEN** 使用者选定某任务类型与账号的组合后没有任何条目
- **THEN** 页面显示说明该组合无结果的提示，两个下拉与其它过滤控件仍可用，使用者可直接改选

### Requirement: 页头只保留过滤控件且不展示页面标题与整页说明

列表页页头 MUST NOT 展示页面标题（例如「稿件核查结论」）与整页说明文案（例如「只读视图：按服务端分页与过滤列出对比结果」）。页头 MUST 只承载列表的过滤控件。

页头的过滤控件 MUST 保持齐备：任务类型下拉、账号下拉、关键词检索与「仅看疑似未审或有差异」勾选项 MUST 全部保留，MUST NOT 因移除标题与说明而减少、隐藏、合并或降级为其它形态。控件的宽度、先后顺序、彼此间距与交互（输入防抖、勾选写缓存、切换回到第一页、运行维度级联）MUST 与既有约定一致。

过滤控件 MUST 在页头内右侧对齐并占据页头整行宽度。移除标题与说明 MUST NOT 在页头留下空容器、空白占位或多余的垂直空白。

移除页头标题 MUST NOT 影响浏览器标签标题：页面 MUST 仍以既有名称作为标签标题，MUST NOT 清空或退回文件名。

#### Scenario: 打开列表页页头

- **WHEN** 使用者打开列表页
- **THEN** 页头不出现「稿件核查结论」或「只读视图：…」这类标题与说明文字，页头只有任务类型下拉、账号下拉、关键词检索与「仅看疑似未审或有差异」勾选项

#### Scenario: 控件在移除文案后仍齐备且右对齐

- **WHEN** 使用者查看收缩后的页头
- **THEN** 任务类型、账号、关键词检索在前，勾选项在后，控件整体贴近页头右缘，检索与勾选行为不变

#### Scenario: 页头不塌陷

- **WHEN** 标题与说明被移除
- **THEN** 页头不残留空容器或占位空白，过滤控件下方与表格之间的间距与移除前一致

#### Scenario: 浏览器标签仍可识别页面

- **WHEN** 使用者切到浏览器标签页视图
- **THEN** 标签标题仍显示该页面的既有名称，不因移除页头标题而变为空或退回文件名
