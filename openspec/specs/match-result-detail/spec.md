# Match Result Detail Specification

## Purpose

把一条匹配成功的核查结论还原成左右两栏的逐行差异对照：两侧正文按相同粒度对齐、差异可就地高亮、记录卡与连线互相对应，并在对齐信息不可用时如实降级。

## Requirements

### Requirement: 详情必须按结论编号取数并区分不可渲染

详情 MUST 以地址中的结论编号向后端详情接口取数，MUST NOT 从列表页的列表项数据拼装正文。

接口返回未找到时（匹配态不为匹配、编号不存在），页面 MUST 呈现明确的"该结论不可渲染"结果与返回列表的入口，MUST NOT 展示空白对照区，MUST NOT 把不可渲染当成"两侧无差异"。

请求失败与请求进行中 MUST 分别呈现失败提示（含重试）与加载状态。

#### Scenario: 直接访问不可渲染的结论

- **WHEN** 使用者直接用一条匹配态为不匹配的结论编号打开详情地址
- **THEN** 页面显示不可渲染结果与返回列表入口，不渲染对照区

#### Scenario: 编号不存在

- **WHEN** 地址中的结论编号在库中不存在
- **THEN** 页面显示未找到，且不报未捕获错误

#### Scenario: 网络失败后重试

- **WHEN** 详情请求失败且使用者点击重试
- **THEN** 页面重新发起同一结论编号的请求，成功后正常渲染

### Requirement: 两侧正文必须按 Markdown 渲染并完整呈现

两侧正文 MUST 按 Markdown 语法渲染为可视内容，MUST NOT 以源码文本形式展示。

对照区 MUST 包含两侧正文的每一个顶层内容块，MUST NOT 存在只为源码视图准备的隐藏区域。

正文中的脚本标签、样式标签与内联事件属性 MUST NOT 被执行，且不得因此影响正文呈现与高亮位置。

#### Scenario: 正文完整呈现

- **WHEN** 任一条结论渲染完成
- **THEN** 两侧正文的每个顶层块都出现在对照区中，没有内容被隐藏

#### Scenario: 正文含脚本或内联事件

- **WHEN** 正文包含脚本标签或内联事件属性
- **THEN** 页面不执行这些内容，正文与高亮位置保持正确

### Requirement: 差异高亮必须按区间注入且不得破坏正文结构

页面 MUST 以结论详情的差异区间为依据，在两侧正文对应位置标出高亮，高亮 MUST 与记录的标识关联，使同一条记录的多处高亮可被同时定位。

无法安全标注的区间 MUST 被跳过（不高亮）而不是被裁剪或强行标注：包括跨段落的区间、边界落在行首块标记上的区间、以及边界切断图片或链接语法的区间。跳过 MUST NOT 中断整篇渲染，MUST NOT 让其余区间失去高亮。

图片类的差异 MUST 以不参与布局的轮廓类样式表达，使图片本身仍然可见。

#### Scenario: 区间安全可注入

- **WHEN** 一条记录的区间完全落在一个段落内部
- **THEN** 该段落对应文字出现高亮，且视觉上不改变段落结构

#### Scenario: 区间跨段落

- **WHEN** 一条记录的区间跨越了空行
- **THEN** 该区间不产生高亮，其余区间照常高亮，页面不报错

#### Scenario: 图片差异

- **WHEN** 一条图片类记录的区间与该侧某张图片在正文中的位置完全重合
- **THEN** 该图片被轮廓标记，图片内容仍然完整可见

### Requirement: 标题必须分列显示且不参与对比行

两侧标题 MUST 分别显示在各自正文列正上方的固定区域并与列宽对齐，标题 MUST NOT 占用对比行、MUST NOT 参与逐行对齐、高亮与连线。

某侧标题缺失时 MUST 显示占位文本，MUST NOT 留空导致表头塌陷。

#### Scenario: 两侧标题

- **WHEN** 详情返回两侧标题
- **THEN** 两个标题分别出现在参考列与发布列正上方，滚动正文时保持可见

#### Scenario: 某侧标题为空

- **WHEN** 某一侧标题为空字符串
- **THEN** 该侧标题位置显示占位文本，另一侧布局不受影响

### Requirement: 对照区必须逐行对齐且只有一个滚动容器

对照区 MUST 只有一个滚动容器，左右两侧 MUST 随同一滚动位置同步移动，MUST NOT 出现两栏各自独立滚动。

行 MUST 以"行原子"为最小单位：顶层段落、标题、代码块、表格、引用、图片各为一个行原子；顶层列表 MUST NOT 整体作为一个行原子，其每个列表项各为一个行原子；列表项内部包含多个段落、嵌套列表或图片时，该项整体仍为一个行原子。

每一侧的每个行原子 MUST 恰好属于一行且顺序与原文一致，MUST NOT 为凑对齐而拆分某个行原子。行高 MUST 取两侧较高者，较短一侧在该行内留白。

某一行只有一侧有内容时，MUST 保留另一侧的空格子并标注内容仅属于哪一侧。

#### Scenario: 滚动对照区

- **WHEN** 使用者滚动对照区
- **THEN** 两侧同步移动，同一行两侧始终处于同一屏幕高度

#### Scenario: 列表逐项与对侧段落成行

- **WHEN** 一侧是包含 N 项的顶层列表，另一侧是对应的 N 个段落
- **THEN** 页面产生 N 行，每行包含一个列表项与一个段落

#### Scenario: 单侧内容

- **WHEN** 某一行内容只存在于一侧
- **THEN** 该侧正常显示内容，另一侧保留空格子并标注内容仅属于哪一侧

### Requirement: 对齐信息不可用时必须显式降级

当结论详情缺少对齐映射、任一侧无法建立"源码位置到渲染块"的对应关系、或行规划自检不通过时，页面 MUST 退回按两侧块的先后顺序配对成行继续渲染，并在页面显著位置标明"未逐行对齐"及原因，MUST NOT 静默声称逐行对齐。

降级时两侧块数量不等 MUST 仍按单侧行处理；高亮、记录列表、连线与定位 MUST 保持可用。

#### Scenario: 缺少对齐映射

- **WHEN** 详情返回的对齐映射为空
- **THEN** 页面按块序配对成行并显示降级提示，不出现错位布局

#### Scenario: 渲染结构与解析结果不一致

- **WHEN** 某一侧的顶层渲染块数量与其源码解析结果对不上
- **THEN** 页面进入降级布局并显示提示，其余功能不报错

#### Scenario: 降级时连线仍可用

- **WHEN** 页面处于降级布局且某条记录的两侧高亮被排到不同行
- **THEN** 该记录仍画出跨行连线，两端与记录的对应关系不变

### Requirement: 差异连线必须按记录配对并可跨行

对每条差异记录，页面 MUST 把两侧命中的高亮按纵向顺序一一配对并画出连线，配对 MUST 只依据该记录自身声明的两侧区间，MUST NOT 依据两侧内容是否被排在同一个行里。

同一条记录的两侧高亮位于不同行时，连线 MUST 跨行连接。当一侧高亮数量少于另一侧时，多出的高亮 MUST 画成只指向单侧的半线并使用与实心端点可区分的空心端点。

连线颜色 MUST 随变化方向区分，且 MUST 与高亮颜色一致。

连线 MUST 随布局变化（行高变化、图片加载完成或失败、窗口尺寸变化）重新贴合高亮位置，MUST NOT 因滚动而改变形状或相对位置。

#### Scenario: 两侧高亮同行

- **WHEN** 一条记录的两侧高亮落在同一行
- **THEN** 该行中缝出现一条连接两侧高亮的连线，两端为实心端点

#### Scenario: 两侧高亮不同行

- **WHEN** 一条记录在参考侧的高亮位于第 3 行、在发布侧的高亮位于第 7 行
- **THEN** 页面画出跨越第 3 至第 7 行的中缝连线

#### Scenario: 一侧高亮更多

- **WHEN** 一条记录在发布侧有 3 处高亮、参考侧有 1 处
- **THEN** 按纵向顺序第 1 处连成实线，其余两处为指向发布侧的虚线半线，参考侧端点为空心

#### Scenario: 图片加载改变行高

- **WHEN** 行内图片加载完成或失败导致行高变化
- **THEN** 连线重新贴合新的高亮位置，行对齐与滚动位置仍然有效

### Requirement: 记录列表必须可定位且不显示记录标识

记录列表 MUST 逐条展示变化方向、内容类型、两侧命中处数与文本摘要。处数的单位 MUST 随内容类型区分（文本与链接按"处"，图片按"张"），某侧没有区间时 MUST 显示"空侧"而不是 0。记录标识 MUST NOT 以可见文本出现，MAY 以不可见属性存在以支撑联动。

文本摘要 MUST 由该记录在该侧的区间从对应正文现场切分得到，MUST NOT 由服务端另设字段下发。

点击记录卡 MUST 使对照区滚动到该记录当前命中行并使其可见；一条记录命中多行时，连续点击 MUST 依次推进到下一命中行、到末尾后回到第一行；切换到另一条记录时游标 MUST 重置。

当前视图找不到该记录任何高亮时，卡片 MUST 给出可见提示，点击 MUST NOT 无反应或报错。

#### Scenario: 记录卡的可见内容

- **WHEN** 使用者查看记录列表
- **THEN** 每张卡片显示变化方向、内容类型、两侧处数与摘要，不出现记录标识

#### Scenario: 连续点击同一条记录

- **WHEN** 一条记录命中 3 行，使用者连续点击其卡片 4 次
- **THEN** 第 1 至第 3 次分别定位到第 1 至第 3 行，第 4 次回到第 1 行

#### Scenario: 记录没有可见高亮

- **WHEN** 一条记录声明的区间都未进入渲染视图
- **THEN** 该卡片显示"无可定位"一类提示，点击不报错

### Requirement: 高亮、连线与记录卡必须联动

悬停任一侧高亮或任一条连线时，该记录在两侧的全部高亮与全部连线 MUST 同时进入强调状态，指针移开后 MUST 恢复为当前选中状态。

点击高亮 MUST 选中该记录并让对应记录卡可见；点击连线 MUST 选中该记录但不改变滚动位置。

#### Scenario: 悬停高亮

- **WHEN** 使用者把指针移到某一侧高亮上
- **THEN** 同一条记录在两侧的所有高亮与连线同时强调，其他记录保持常态

#### Scenario: 点击连线

- **WHEN** 使用者点击一条连线
- **THEN** 对应记录被选中，滚动位置保持不变

### Requirement: 无差异结论必须正常渲染

匹配成功但差异记录为空的结论 MUST 正常渲染两侧正文与逐行对照，MUST 在记录区域明确提示"两侧一致"，MUST NOT 呈现为错误或空白页面。

此时页面 MUST NOT 出现任何高亮与连线，且 MUST NOT 显示降级提示（对齐信息正常时）。

#### Scenario: 两侧完全一致

- **WHEN** 打开一条差异记录为空的结论详情
- **THEN** 两侧正文正常逐行对照，记录区域显示"两侧一致"，页面无高亮、无连线、无降级提示
